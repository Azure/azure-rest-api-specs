01

Decisions locked

These boundaries keep the implementation small, portable, and recoverable.

Source of truth ADO artifacts

Each completed build publishes an immutable report artifact. Retention leases create the historical window.

Derived cache SQLite

The dashboard cache can be deleted and rebuilt by enumerating retained pipeline artifacts.

Not in scope No Kusto

No ingestion service, table mapping, or duplicate recovery path is introduced for Phase 3.

Existing surface Extend the dashboard

The deployed Vally App Service is the integration target. A second reporting application is unnecessary.

Ownership rule

All changes under eng/common start in Azure/azure-sdk-tools and flow through the established sync process. The specs repository owns only its repo-local pipeline configuration and hooks.

03

Seven-PR delivery roadmap

Each stage is independently reviewable and has a concrete exit check.

1

Result contract

Make scenario identity and outcome meaning stable across repositories and refactors.

azure-sdk-tools
Foundation

Deliver

  • Versioned normalized JSONL, manifest, and CSV schemas
  • scenario_id and scenario_version tags
  • Uniqueness validation and deterministic failure classifier
  • Migration of every existing stimulus to an explicit ID
Exit checkRenaming an eval file or stimulus leaves its historical identity unchanged.
2

Shared report generator

Turn raw Vally records into portable run data and inspectable evidence.

azure-sdk-tools
Depends on PR 1

Deliver

  • build-eval-report.ts under shared eval scripts
  • Highest-attempt selection for rerun-safe aggregation
  • One self-contained, escaped HTML trajectory per scenario
  • Contract tests for malformed, legacy, and hostile inputs
Exit checkA synthetic multi-shard run produces deterministic JSONL, CSV, summary, and HTML.
3

Shared pipeline integration

Make reporting a standard Summary-stage capability for every eval consumer.

azure-sdk-tools
Depends on PR 2

Deliver

  • Always publish raw JSONL and JUnit from each shard attempt
  • Download, dedupe, and render in eval-summarize.yml
  • Publish one consolidated eval-report-<attempt>
  • Add tier, category, and retention parameters to the archetype
Exit checkA failed shard still contributes evidence and cannot double-count after rerun.
4

Entrypoints and retention

Enable the common path in all three pipelines and establish the trend window.

tools + specs
Depends on PR 3

Deliver

  • Configure skill, workflow, and live eval metadata
  • Run retain-run.yml under condition: always()
  • Apply 731-day main/nightly and 90-day PR/manual policies
  • Verify leases and artifact downloads through ADO APIs
Exit checkOne completed build of each pipeline has the expected report and lease.
5

Dashboard ADO sync

Replace manual result upload with an authenticated, rebuildable artifact pull.

dashboard
Depends on PR 4

  • Raw Vally ingestion plus manifest/history extension tables
  • Removal of production Kudu upload and basic SCM credentials

6

Consolidated dashboard UX

Expose framework-wide trends while preserving Vally's detailed drill-down.

dashboard
Depends on PR 5

  • Pipeline, repository, tier, area, model, and branch filters
  • Stable scenario history plus build and trajectory links

7

AI trend reports

Summarize deterministic changes and propose reviewable follow-up work.

dashboard + pipeline
Depends on PR 6

04

Artifact contract

The build artifact is portable, inspectable, and sufficient to rebuild reporting.

eval-report-<attempt>/
|-- manifest.v1.json
|-- normalized-results.v1.jsonl
|-- history.csv
|-- eval-summary.md
|-- trajectories/
|   `-- <scenario-id>.html
|-- raw/
|   `-- <shard>/results.jsonl
`-- junit/

Each artifact is immutable. The dashboard logically appends per-build CSV fragments and offers a consolidated download.

06

End-to-end exit gates

Phase 3 is complete only when all six behaviors hold in production.

1
Complete artifacts

Every pipeline publishes raw, normalized, CSV, summary, trajectory, and JUnit outputs.

2
Stable history

Scenario renames and file moves do not split trend lines; semantic changes increment version.

3
Correct reruns

The highest job attempt supersedes earlier attempts without duplicate trials or scenarios.

4
Durable retention

Main and nightly builds carry verified 731-day leases; PR/manual builds carry 90-day leases.

5
Automatic dashboard

New reports appear through ADO sync with no Kudu upload or database maintenance.

6
Evidence-linked insight

Dashboard and AI regressions link to the source build and an inspectable trajectory.

Critical path

Contract and IDs > report generator > shared pipeline artifact > retention > dashboard sync > trend UX > AI analysis. Dashboard authentication can proceed in parallel with PRs 1 through 4.
