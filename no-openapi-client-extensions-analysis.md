- **Base commit:** [`1345d69b2b`](https://github.com/Azure/azure-rest-api-specs/blob/1345d69b2b0a556c3b282a0ae4e2896e8b6155b9) (`typespec-next`)

- **Spec files affected:** 70
- **Services affected:** 30
- **Reference date for priority:** 2026-08-06

The diagnostic count is much larger than the number of unique decorators because many parameter/operation templates are instantiated repeatedly; each instantiation re-reports the same source location. The detail table below is keyed by unique decorator location and records how many diagnostics each produced.

## What the rule flags and why it matters

The `@typespec/openapi` `@extension` decorator writes a raw property into the emitted OpenAPI document. For the `x-ms-*` / `x-*` keys below, that property is **client-altering**: it changes how an SDK, the ARM platform, or another emitter is supposed to interpret the API. Because only the OpenAPI emitter sees it, every other emitter (TCGC / client SDKs, service code, etc.) produces an representation that disagrees with the OpenAPI output. Each key has a first-class TypeSpec construct that all emitters honor.

| --- | --- | --- | --- | --- |

| `x-ms-client-name` (13) | Renames a property / parameter / model in generated clients. | `@clientName` in `client.tsp` (typespec-client-generator-core) | True positive | — |

| `x-ms-secret` (6) | Marks a property as a secret (write-mostly / redacted). | the `@secret` decorator | True positive | — |

| `x-nullable` (6) | Marks a schema as nullable (Swagger 2.0 nullability). | a nullable type: `T | null` | True positive | — |

| `x-ms-enum` (1) | Controls the generated SDK enum name and whether it is modeled as an (open) string. | a named `enum` (closed) or `union` (open, `string`-based), with `@clientName` for naming | True positive | — |

**`x-ms-long-running-operation-options`** — Same as x-ms-long-running-operation: the final-state hint only reaches OpenAPI. Where the operation is *already* modeled as an LRO, the impact is limited to the final-state override.

**`x-ms-parameter-grouping`** — Parameter grouping is realized by TCGC from parameter models. Emitted as a raw extension it is invisible to clients, which get flat, ungrouped parameters.

**`x-ms-long-running-operation`** — LRO behavior (polling, final-state) is generated from the modeled LRO templates. Set via a raw extension it is invisible to clients, which treat the call as synchronous. LintDiff rules that require this extension (or a specific value) are, by construction, unsatisfiable for TypeSpec clients when it is emitted this way.

**`x-ms-parameter-location`** — Client/method placement is a client concern owned by TCGC. The raw extension only lands in OpenAPI, so the SDK places the parameter differently.

**`x-ms-azure-resource`** — ARM resource semantics are provided by the resource-manager library. If the model is already a library resource the extension is redundant; if it is not, the raw extension does not make clients/ARM tooling treat it as one.

**`x-ms-client-name`** — `@clientName` is the first-class, emitter-aware rename. The raw extension is ignored by TCGC, so the SDK keeps the wire name.

**`x-ms-client-flatten`** — Flattening is a client transformation TCGC does not read from the raw extension. Migration usually means removing the flattening and modeling explicitly.

**`x-ms-secret`** — Secret semantics reach clients/tooling through `@secret`. A raw extension is ignored, so SDKs do not treat the value as secret.

**`x-ms-pageable`** — Paging is a first-class Azure.Core pattern that clients use to generate iterators. The raw extension is ignored, so the SDK returns a single unpaged response.

**`x-nullable`** — Nullability must be part of the TypeSpec type for clients to see it. Emitted only as an extension, the SDK type stays non-nullable and disagrees with the service.

**`x-ms-skip-url-encoding`** — Only affects the OpenAPI document. TCGC and non-OpenAPI emitters URL-encode the value, so generated SDKs build a different (encoded) URL than the service expects.

**`x-ms-enum`** — Enum naming / model-as-string is an SDK concern that TCGC derives from the TypeSpec type, not from the OpenAPI extension. Clients get an anonymous/incorrectly-modeled enum.

### Notes on nuanced cases

- **`x-ms-long-running-operation` / `-options`:** where the operation is *already* modeled as an LRO (a `@pollingOperation` or an Azure.Core/ARM LRO template is present), TCGC clients still get LRO behavior; only the extension-supplied option (e.g. `final-state-via`) is lost. These are flagged **modeled-LRO (low impact)** in the detail table.

- **`x-ms-azure-resource`:** where the decorated model is already a resource-manager library resource (`TrackedResource`/`ProxyResource`/`ExtensionResource`), the extension is redundant and the emitted OpenAPI is already correct — a **likely false positive (redundant)**, flagged **modeled-resource** below. The fix is simply to delete the redundant extension.
